# 整词选词的 A/B（2026-11-04，同一 checkpoint，不重训）

目的：验证"纯标点硬屏蔽 + 同名词去重"这一处改动**单独**带来多少变化。
为了只让"选词"这一个变量变化，两次运行**都**用同一套注入口径
（`--inject-mode user --fence-style bracket`）和同一个 checkpoint
（`ckpt/hotpot_router_10k_v5.pt`，它是**旧方法**训出来的，所以绝对分数只作对照）。

- **before** = `6a5961b`：纯标点降权 0.1（仍可能被选中），没有去重
- **after** = `ed6fe9f`：纯标点 `pen=0` → 候选集里 `-inf` 屏蔽；同表面键去重；有效词不足时留空位

## 一、符号覆盖诊断（val500 前 50 题，固定样本，答对答错都统计）

| 指标 | before | after | 变化 |
|---|---|---|---|
| 命中率（任一答案词） | 39.6% | **49.1%** | +9.5 |
| **完整答案覆盖** | 13.2% | **24.5%** | **+11.3** |
| 数字完整保留 | 8.3% | 8.3% | 0 |
| **无效选择比例** | 47.8% | **28.2%** | **−19.6** |
| 被选词总数 | 876 | 820 | −56 |

- 无效选择比例的剩余部分**全部是停用词**（`was`/`in`/`the` 等，只降权到 0.35、仍可选）。
  纯标点已经被完全排除，符合本轮设计。
- 数字覆盖率没动：这一批样本里含数字的答案槽太少（53 个槽里只有个位数），
  单看这一列下不了结论。
- 原始数据：`symbol_fidelity_before.json` / `symbol_fidelity_after.json`（含逐题、逐槽明细）。

## 二、Oracle Latent EM（val500 前 200 题）

| 指标 | before | after | 变化 |
|---|---|---|---|
| acc | 11.0% | **13.5%** | **+2.5** |
| EM | 11.0% | **13.5%** | **+2.5** |
| F1 | 0.198 | 0.233 | +0.035 |
| 注入 token | 30.2 | 30.2 | — |
| 其中内容 / 围栏 | 17.9 / 12.2 | 17.9 / 12.2 | — |
| prompt token | 83.5 | 83.5 | — |
| 每题耗时 | 3136 ms | 3055 ms | — |
| 隔离模式 | `fence_only:attn_impl=sdpa` | 同 | — |

- 注入 token 从旧长围栏的 **64.5** 降到 **30.2**（内容 17.9 + 围栏 12.2），
  这是 v6 手术一（bracket 围栏）的效果，两次运行相同。
- 原始数据：`oracle_latent_before.json` / `oracle_latent_after.json`。

## 三、怎么读这两个数

1. **改动方向是对的**：无效槽位少了 20 个百分点，完整答案覆盖翻倍，EM +2.5。
2. **但绝对值仍然很低**（13.5% vs 明文 oracle 54.0%）。原因有两层：
   - checkpoint 是**旧方法**（按子词选 + 消息之间注入）训出来的，现在换了选词粒度与注入位置，
     训练/推理不同构 —— 这个 13.5% 不能当"新方法的上限"；
   - 即使排除这一点，每块 32 token 只带 4 个词，信息量本来就有限。
3. 结论：**这处修复可以保留**，但要看到真实效果必须重训一轮（`runs/run_stage2_bridge.sh` 已带 v6 开关）。

## 四、仍未解决

- 停用词仍占 28.2% 的槽位（只降权、不屏蔽）。是否也要硬屏蔽，需要单独实验。
- `[Smyrna` 这类带前导标点的词，聚合向量里仍混着 `[` 的嵌入（词形保真问题，下一步）。
- 数据集本身有脏文本（例如混入 `{'1': ", ...}` 字面量），会造出 `183022` 这种假词。
