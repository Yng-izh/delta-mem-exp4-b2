# E1 的结果：梯度隔离**没有**救回语义读出（2026-11-05）

一句话：**E1 的假设被证伪了。** 把 L_cov 的梯度关在独立词形头里，机械上完全成功
（单测 + 真机梯度都对得上），但读出端一个点都没回来 —— 三条读法与"共享注意力"那组
几乎逐位相同。所以语义退化**不是** L_cov 的梯度造成的。

## 设置

| 项 | 值 |
|---|---|
| 权重 | `ckpt/probe_e1_lexhead.pt`（1000 步，`--cov-weight 0.1 --lex-head 1`） |
| 对照 A | `ckpt/probe_base_1000.pt`（1000 步，`cov=0`） |
| 对照 B | `ckpt/probe_cov_1000.pt`（1000 步，`cov=0.1`，**共享注意力**） |
| 三组共同点 | 同一批数据/同 seed/同超参，只差 `--cov-weight` 与 `--lex-head` |
| 评测 | `hotpot_val500` 前 200 题，金标槽直送，注入 30.17 token，判定 = 归一化整串相等 |

## 结果

| 读法 | A 无 cov | B 共享注意力 | **E1 隔离** | A vs E1 | B vs E1 |
|---|---|---|---|---|---|
| `oracle_lex` | 35/200 = 17.5% | 32/200 = 16.0% | **30/200 = 15.0%** | 11 比 6，p=0.33 | 12 比 10，p=0.83 |
| `oracle_sem` | **28/200 = 14.0%** | 14/200 = 7.0% | **12/200 = 6.0%** | **17 比 1，p=0.0001** | 9 比 7，p=0.80 |
| `oracle_latent` | 36/200 = 18.0% | 29/200 = 14.5% | **29/200 = 14.5%** | 13 比 6，p=0.17 | **9 比 9，p=1.00** |

配对检验 = McNemar 精确二项（同一批 200 题逐题配对）。

**最刺眼的一行是 `oracle_latent` 的 9 比 9**：隔离组和共享组在组合读出上**逐题同分**，
连胜负分布都是对称的。也就是说这次改动对读出端的影响是零。

## 隔离本身是成功的（所以这不是"没做对"）

真机对照（同一批 12 条、同 seed、pack=4，第 1 步）：

| | queries | attn | input_proj | lex_scorer |
|---|---|---|---|---|
| `--lex-head 0` | 2.24e-03 | 6.46e-03 | 3.30e-06 | 0 |
| `--lex-head 1` | **0** | **0** | **0** | **1.13** |

第 0 步两臂的 `cov_pcov`（0.425）、`loss_qa` 逐位相同，`lex_scorer` 零初始化的等价性成立。
所以"梯度确实没进语义注意力"这件事是钉死的 —— 正因如此，结论只能是
**梯度共享不是原因**，而不是"实验没生效"。

## 那原因是什么

三条线索指向同一个方向：**问题出在"选了哪些词"，不在梯度走哪条路。**

1. **B 和 E1 的读出几乎一样**，而两者的选词机制完全不同（一个是注意力自己学，
   一个是独立头学）。两者唯一的共同点是**都在优化同一个覆盖目标**，于是选出的词
   性质相近。
2. **E1 的独立词形头学歪了**：50 题符号保真里**无效选择率 18.3%**（820 个被选词），
   而共享注意力那组 200 题是 **2.5%**；同一个头在第 3 步时只有 2.2%。
   覆盖率高（49.1%）但槽位里塞了不少标点/停用词 —— 覆盖目标只管"重要词有没有被覆盖"，
   不管"剩下的槽位放什么"。
3. **语义分支被饿着**：`recon-lex 1` 让重建也走 `bridge(z_sem, z_lex)`。选词一旦被
   覆盖目标改得"更像关键词袋"，重建就更容易靠 z_lex 满足，z_sem 分到的信号变少。
   证据：E1 的 Bridge 末层权重范数 `|Wlast|` = 4.91，而 base 是 6.70（B 是 5.87）——
   语义分支确实长小了。

这三条都还只是**假设**，需要下一轮验证（最便宜的检验：`--recon-lex 0` + `cov=0.1`，
如果 `oracle_sem` 回来了，第 3 条成立）。

## 按决策树，这一轮该怎么走

E1 属于预案里的 **❌ 失败**分支：`oracle_sem` 没恢复 → **语义退化另有原因，别再调 cov
权重**。具体地：

- **不要**再试 `cov=0.02/0.03`（那还是在同一个错误方向上做微调）；
- **不要**重训正式模型；
- E2（原生 BPE，零训练）仍然值得做，但它的前提"E1 证明词形选择有收益"没成立 ——
  现在 E2 的价值只剩"子词均值是不是 `oracle_lex` 的瓶颈"这一个问题，优先级下调；
- 下一步应该是**查 z_sem 这条路径**：`--recon-lex 0` 的对照，以及覆盖目标对选词分布的
  副作用（18.3% 无效选择这一条要单独查清楚）。

## 附带发现（与结论无关，但该记）

- 训练 1000 步里 `cov_pcov` 0.449 → 峰值 0.651（step 210）→ 回落到 0.58~0.62 平台；
  而共享注意力那组是 0.404 → 0.627 **单调上涨**。独立头学得更快、更早饱和、后期回退。
- 训练期 val full-match：12.5% → 17.5%（step 500）→ 15.0%（收尾）。40 题样本，
  ±5.6 个点的噪声，不足以说明什么。
- `--diag-every` 的 α / res/lex 统计有个**已存在的差一位**：统计在 `step % 50 == 0` 的
  样本上采集，但打印在 `[step N+1]` 那一行，所以日志里按 `[step 50]` 去找 α 会找不到。
  不影响结果，但看日志时容易误判"没打"。
