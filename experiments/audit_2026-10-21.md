## 0. 读法与强制口径

**这张表不是成绩单，是"能对外说多少"的边界。** 三种状态必须严格区分，不得混写：

| 标签 | 含义 |
|---|---|
| **已修** | 代码落地 + 有断言覆盖 + 口径无已知缺陷 |
| **部分修** | 主干落地，但有明确的能力缺口（缺口写在"口径限制"列） |
| **已实现·仅合成验证** | 代码与单测都在，但仓库里没有能喂它的真实数据，效果未知 |
| **已实现·待接线** | 代码在库里、单测通过，但评测主路径没调用它 → 线上不生效 |
| **未修** | 明确没做，或做了但不能用 |
| **未验证** | 机制在，但"它到底有没有用"没有任何对照数据 |

特别声明（本轮不得违反的表述纪律）：
1. `topk_refresh` 是**词面 IDF 近似**，不是"检索器驱动的刷新" → 只能写"部分实现"。
2. Delta 是否提升问答 → **未验证**（默认仍 `AR_DELTA_WRITE=0`，三档策略一次对照都没跑）。
3. CR 2 跳 → "已实现 + 已知双向风险"（漏链 / 误拒覆写），两项由 t19 量化，**不得**写"已验证"。
4. EventQA 窗口方向 → **未定论**（配对检验 Holm 后 12 对全不显著，MDE=9.7pp，默认 16/4 仅"暂留"）。
5. 证据级召回 → 真实数据仍无金标 span，**未修**；t20 若产出只能标"合成数据"。
6. 四格联合归因 → 已实现且有 selftest + 合成手算核对，但仓库**没有一条带 diag 字段的真实 jsonl** → "仅合成验证"。
7. LongMemEval 三项能力 → 代码已实现（`readout(mode="lme")`），但 **runner 仍走 `mode="topk"`** → "已实现、待 t21 接线后才能在评测中生效"。
